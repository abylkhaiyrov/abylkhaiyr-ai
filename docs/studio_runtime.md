# Studio: состояние выполнения и события

## Единый источник состояния
`RuntimeState.snapshot()` собирает состояние из `state.json` конвейера, `progress.json` этапов, `metrics.jsonl`
обучения, конфигураций и процесса `run_pipeline.py`. Все страницы Studio читают одну структуру (`GET /api/runtime`,
событие `runtime.update`). Состояние кэшируется на 1 с, сканирование процессов — на 3 с.

Стадий десять: подготовка данных, токенизация, предобучение, оценка предобучения, выбор лучшего checkpoint, SFT,
оценка SFT, DPO, финальная оценка, экспорт. Подготовка данных и токенизация определяются по артефактам на диске.
Если процесс не жив, а стадия в `state.json` «running», стадия показывается как `interrupted`.

## Прогресс без выдуманных значений
Процент считается только при известном общем числе операций. Для оценки без телеметрии (запуск, начатый до
появления инструментирования) возвращается `indeterminate: true`, а UI показывает неопределённый индикатор.
ETA оценки считается по средней длительности уже проверенных checkpoint и недоступен до первого.

## ProgressTracker
`llm.progress.ProgressTracker` пишет `progress.json` атомарно и с ограничением частоты (0,5 с). Его используют:
- `TrainingMonitor` (шаги, фаза `training`/`validation`/`checkpoint`, ETA) — файл рядом с `metrics.jsonl`;
- `TrainingPipeline` через `StageEvaluationHooks` — checkpoint i из N, бенчмарк, проверено/осталось задач,
  скорость, промежуточные метрики.
Формат обратно совместим: `state.json` не менялся, старые запуски читаются без `progress.json`.

## WebSocket
Одно соединение на вкладку, события типизированы (`studio/events.py`), каждое получает `seq` соединения.
Heartbeat каждые 15 с, клиент переподключается с экспоненциальной паузой и заново подписывается; активные
генерации восстанавливаются снимками. У каждого соединения ограниченная очередь отправки: телеметрия при
переполнении отбрасывается, медленный клиент отключается. Повтор `request_id` идемпотентен (SQLite).

## Реестр моделей
Роли: `production` (манифест `checkpoints/production.json`, иначе экспортированный финальный checkpoint),
`best_evaluated`, `latest_trained`, `loaded`. Проверенными считаются checkpoint, прошедшие оценку и выбор.
Смена модели во время генерации запрещена (`409 generation_active`); у каждого ответа сохраняются модель и checkpoint.
