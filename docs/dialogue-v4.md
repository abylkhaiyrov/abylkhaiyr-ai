# Dialogue v4

Рабочая Studio использовала `checkpoints/tiny_gpu_sft/best`, SFT шаг
1300. Аудит загрузил все восемь доступных сохранений. Для каждого были
проверены контрольные суммы, конфигурация и отпечаток токенизатора.
Архитектура содержит 15 735 168 параметров и контекст 512 токенов. DPO
checkpoint в локальном наборе отсутствовал.

При исходных настройках CLI и живой HTTP API на «Как дела?» вернули
«Я не вижу, какой именно вариант вы имеете в виду. Уточните, что мы
сравниваем.» При едином профиле temperature 0,3, top-k 40, top-p 0,9,
repetition penalty 1,1 и seed 42 ответ рабочей модели был
«Меня зовут Abylkhaiyr AI.» Этот ответ также получен через WebSocket Studio
с greedy. При одинаковом коротком контексте ошибка воспроизводится без
браузера. Первопричина в данном случае связана с качеством модели.

Тест длинного диалога выявил отдельную проблему в формировании контекста.
Система считала длину диалога одним способом, а затем могла обрезать
сырые токены и оставить сообщение без его маркера роли. Новая обрезка
удаляет старые ходы целиком, сокращает длинное содержимое по границам
Unicode и сохраняет BOS, маркер последней роли, EOS и маркер ассистента.
HTTP API подсчитывает фактически переданные токены и сообщает реальную
причину остановки потока. Декодер распознаёт маркеры всех ролей как границы
ответа. CLI проверяет размер словаря и отпечаток токенизатора перед загрузкой.

У Reasoning Engine эвристики повтора запроса, зацикливания и остановки
влияют на оценку кандидата. Статус «проверено» не присваивается свободному
тексту только за правдоподобный вид. Итерации ограничены существующим
бюджетом. Локальный классификатор по символьным признакам обучен отдельно.
Он правильно классифицировал 17 из 48 запросов и воздержался на 23.
Исходная маршрутизация правильно обработала 23 из 48. Экспериментальный
классификатор не включён в маршрутизацию.

## Данные и обучение

В корпус добавлены диалоги людей из закреплённой версии OpenAssistant
OASST1. Использовались данные с заявленной лицензией Apache-2.0,
оценками качества и разметкой ответов. Открытые данные дополняют
проверенные примеры разговорной речи на русском, английском и казахском,
существующие SFT-группы и упражнения с вычисляемыми ответами. Ответы
обучаемой модели не добавлялись в качестве эталонов.
[Карточка источника](https://huggingface.co/datasets/OpenAssistant/oasst1).

Проверка фактических бинарных labels подтвердила маскирование BOS,
маркеров ролей и всех пользовательских токенов. Текст ассистента и его EOS
участвуют в loss. В прежних данных найдено 18 точных пересечений отдельных
запросов train/test. В итоговом v4 после фильтрации осталось 21 740
обучающих и 375 валидационных диалогов. Из обучающих диалогов 1940
многошаговых. Точных пересечений полных диалогов между train и validation
нет. 84 одинаковые короткие реплики встречаются в разном контексте.
Контрольные запросы и пользовательские реплики их истории исключены
из новых обучающих файлов.

В раннем прогоне обнаружена отдельная утечка при ручной проверке.
OASST содержал точный вопрос «Как дела?» и ответ «Спасибо, хорошо.
Я постоянно совершенствуюсь и развиваюсь. …». Кандидат воспроизвёл его
через HTTP и WebSocket. Такой ответ исключён из независимой оценки.
Этот запрос добавлен в список исключений, после чего обучение повторено
от исходного SFT checkpoint. Ещё один повтор исправил пересечение
полных диалогов между train и validation у структурированных упражнений.

Режимы SFT использовали RTX 4070 SUPER, BF16, микробатч 16, два
накопления градиента, окно 383 и 12% языкового replay. Для общего SFT
сравнены старт с pretrain (LR 0,00025) и продолжение старого SFT (LR
0,00012). Оба завершились на шаге 450 после четырёх проверок без
улучшения. Для целевого обучения контекста использовался LR 0,00009.
Состояние сохранялось каждые 150 шагов, валидация шла каждые 75 шагов.

## Независимые проверки

Набор содержит 557 автоматических проверок. 504 из них — контролируемые
варианты простых инструкций, числовой памяти, исправления предыдущего
значения и арифметики. Остальные 53 — исходный набор диалоговых сценариев.
Контролируемые варианты измеряют конкретные навыки и не представляют
557 разнородных человеческих диалогов. Свободные ответы, включая
«Как дела?», переводы, опечатки, смену темы и исправление ошибки,
просмотрены отдельно. Общая частота галлюцинаций и естественность
на репрезентативной выборке не измерены.

| Веса | Все проверки | Точная простая инструкция | Точный multi-turn |
|---|---:|---:|---:|
| Работающий SFT | 12,75% | 42,86% | 0% |
| Общий v4 с pretrain, шаг 300 | 5,92% | 16,67% | 0,79% |
| Общий v4 с SFT, шаг 450 | 15,80% | 57,94% | 0% |
| Первый контекстный SFT, шаг 375 | 15,44% | 27,78% | 23,02% |
| Повтор после удаления пересечений, шаг 450 | 15,62% | 25,40% | 26,98% |

Последний прогон занял 41,7 с, пик выделенной GPU-памяти составил 1,87 GiB,
скорость с replay составила 30,7 тыс. целевых токенов/с. Perplexity на
32 отложенных окнах снизилась с 157,89 до 33,53. Точный числовой контекст
вырос с 3,76% до 8,27%, нормальное завершение с 87,61% до 96,95%,
а повторы триграмм снизились с 2,36% до 0,76%. Эхо в начале осталось
на уровне 0,18%, точная арифметика на 0%. Greedy с KV-cache и без него
совпал по токенам на трёх проверенных диалогах у обоих checkpoint.

| Запрос | Работающий SFT | Итоговый кандидат |
|---|---|---|
| Как дела? | Меня зовут Abylkhaiyr AI. | Вас зовут Abylkhaiyr AI. |
| как дила | как дила дила — это чёткая последовательность шагов, которая решает задачу или помогает выполнить какое-либо действие. | Понятно. |
| Как меня зовут? (имя Аскар в истории) | Вас зовут Аскар. | Вас зовут Аскар. |
| Сколько будет 125 * 48? | 125 * 48 = 108. | 125 * 48 = 108. |

Модель всё ещё подменяет намерение пользователя и путает собственное имя
с именем собеседника. Точные простые инструкции ухудшились. Целевые
значения не достигнуты, и версия не принята. Эксперимент измеряет
поведение имеющейся конфигурации на конкретных данных. Предел качества
для архитектуры такого размера отдельно не установлен.

Отдельная проверка Code Pass@1 дала 0 из 24 на рабочей модели, общем
SFT шаге 450 и первом контекстном SFT. Набор проверяли на реально
сгенерированном коде. Ни один из этих ответов не прошёл разбор Python.
Проводилось сравнение greedy и трёх профилей sampling, а также
условия с текстовой stop sequence. Режим декодирования заметно менял
ответы на короткие реплики, но не устранил слабое понимание контекста.

Условиями публикации v4 служат отдельная ручная оценка базового
диалога, 85% простых инструкций, 80% multi-turn, лимиты на эхо и
бессвязность и отсутствие регрессии по языкам. Дополнительно действует
существующая проверка удержания языковой модели на perplexity.
Кандидаты хранятся вне каталога активных checkpoint. Studio при
запуске сначала проверяет указатель на принятую версию. Отклонение
кандидата сохраняет прежнюю запись. `scripts/promote_model.py --rollback`
возвращает предыдущую принятую версию при её наличии. DPO не запускалось.

Локальные отчёты хранятся в `experiments/dialogue_v4`. Для повтора
используются `scripts/prepare_dialogue_v4.py`,
`scripts/prepare_grounded_dialogue.py`,
`scripts/train_dialogue_v4.py`, `scripts/evaluate_dialogue_v4.py`
и `scripts/probe_dialogue_api.py`. Собственные веса, исходный Parquet,
расшифровки ответов и бинарные файлы обучения хранятся локально.
