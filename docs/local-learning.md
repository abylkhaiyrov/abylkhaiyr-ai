# Непрерывное обучение и локальный агент

Аудит проведён на RTX 4070 SUPER с PyTorch 2.11.0+cu128. Все восемь
проверенных сохранений содержат decoder-only Transformer с 15 735 168
параметрами, восемью слоями, шириной 384, шестью query-головами и двумя
KV-головами. Контекст составляет 512 токенов, словарь Byte-Level BPE
содержит 8192 элемента. Токенизатор точно восстановил 30 из 30 текстов.
Дедуплицированный корпус содержит 32 835 604 обучающих позиции. На шаге
3226 обработано 105 709 568 позиций с повторным использованием корпуса.
Уникальность последовательностей внутри документов отдельно не измерялась.

Perplexity измерена на 32 окнах тестового корпуса. Диалоговая оценка

повторения и улучшило реакции на вопросы, но повысило perplexity базового
корпуса. У модели остаются провалы на задачах с контекстом, программированием

## Цикл обучения

В `experiments/learning_inbox/sources.json` оператор указывает разрешённые
относительные файлы и их лицензии. Файлы содержат JSONL с полями
`prompt` и `answer`. Цикл проверяет заявленную лицензию по списку,
очищает текст, проверяет язык и качество, исключает совпадения с известными
заданиями оценки и определяет split по нормализованному запросу.
Происхождение файла и условия лицензии проверяет оператор.

Первый источник подготовлен генератором `--seed-math` с проверкой SymPy.
Цикл принял 94 обучающих и 19 валидационных примеров и сделал 60 шагов.
Perplexity на 48 отложенных окнах снизилась с 165,74 до 155,65.
Диалоговый результат вырос с 26,42% до 30,19%, результат русского языка
снизился с 20% до 15%. Точная арифметика осталась на 0%.
Кандидат отклонён. Полный отчёт записан в `state.json` цикла.

Повторный запуск возобновляет веса прерванной версии. Контроллер выполняет
ограниченное число проверок. Неизменившийся набор не обучается повторно.
При публикации цикл устанавливает указатель для следующего запуска Studio.
Флаг `--rollback` возвращает указатель к предыдущим весам.
Автозапуск после перезагрузки Windows пока отсутствует.

## Агент разработки

Задача задаётся JSON с полями `instruction`, `cases` с парами
`stdin` и ожидаемый `stdout`, `attempts` и `seconds`. Эталоны остаются
у контроллера. Он компилирует код и запускает каждый тест в отдельном
контейнере без сети, монтирования хоста и записи в корневую файловую
систему. Вывод, память, CPU, количество процессов и время ограничены.
Ошибка передаётся модели для следующей попытки, а `solution.py`
сохраняется после прохождения всех тестов.

```powershell
$image = docker image inspect python:3.12-slim --format '{{.Id}}'
.venv\Scripts\python.exe scripts/run_developer_agent.py task.json --image $image --output experiments/task
```

В автономной задаче на сложение собственная модель дала 0 из 5
компилируемых ответов. Отдельный прогон `scripts/evaluate_developer_agent.py`
дал 0 из 4 решённых задач за три попытки на каждую. Он проверяет сложение,
сортировку, исправление обработки строки и SQL. Контейнерная проверка выполнила отдельную
контрольную программу и проверила таймаут и изоляцию.
Для Python-проверок Reasoning Engine используется тот же контейнер при
указании ID образа в `ABYLKHAIYR_SANDBOX_IMAGE`.
Репозиторные правки, установка зависимостей, долговременная память
и произвольные многокомпонентные ТЗ пока за пределами этого агента.
