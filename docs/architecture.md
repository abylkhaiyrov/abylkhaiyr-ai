# Архитектура проекта

```
core/        конфигурации (pydantic), ошибки, определение оборудования, профили моделей
model/       RMSNorm, RoPE, SwiGLU, Attention (GQA, KV cache), TransformerBlock, CausalLM
tokenizer/   Byte-Level BPE, специальные токены, шаблон диалога, маски SFT
data/        очистка, PII, язык, MinHash-дедупликация, источники, memmap-загрузчики
optimization/ AdamW, расписание LR, клиппинг, точность, контроль памяти
training/    Objective (LM, DPO), Trainer, чекпойнты, мониторинг, сборка сессии
inference/   сэмплирование, KV cache, стриминг, beam search, пакетная генерация
reasoning/   песочница, инструменты (SymPy), Reasoning Engine с бюджетом
evaluation/  метрики и независимые наборы задач
api/         локальный OpenAI-совместимый REST API
cli/         команда `llm`
```

## Принципы
- Зависимости направлены вниз: `cli -> training/inference/evaluation -> model/data/optimization -> core`.
- `Trainer` не знает о конкретной задаче: потери задаёт `Objective` (`CausalLMObjective`, `DPOObjective`).
- Источники батчей реализуют `BatchSource` (`PackedTokenLoader`, `ConversationLoader`, `PreferenceLoader`).
- Ошибки — иерархия `LLMError`; CLI превращает их в код возврата.

## Формат диалога
`<bos> <system> текст <eos> <user> текст <eos> <assistant> текст <eos>`. Специальные токены кодируются только
программно: строка `<eos>` в пользовательском тексте превращается в обычные символы. В SFT потери считаются
только на токенах ответов ассистента (включая `<eos>`).

## Данные
Корпус очищается и фильтруется, затем дедуплицируется (точно и MinHash/LSH) **до** разбиения на train/validation/test.
Поэтому близких дубликатов между выборками нет. Раздельные дедупликаторы для корпуса и SFT-примеров, потому что
один датасет может законно входить в обе группы. Источники, лицензии и счётчики отбраковки пишутся в `manifest.json`.
Токены хранятся в `uint16` и читаются через `np.memmap`.

## Чекпойнты
Каталог `step-XXXXXXXX/` с `model.safetensors`, `training_state.pt` (оптимизатор, scaler, RNG, состояние загрузчика,
метрики) и `meta.json` (конфигурация, версия токенизатора, SHA-256 файлов). Запись идёт во временный каталог и
атомарно переименовывается. Возобновление берёт последний чекпойнт с корректными контрольными суммами.

## Песочница
Генерируемый код запускается в отдельном процессе: `python -I -S`, пустое окружение, временный каталог, лимиты CPU,
размера файлов и дескрипторов, таймаут, блокировка `socket`/`subprocess`/`os.system`. Это защита от случайных
ошибок, но не изоляция уровня контейнера: лимит памяти `RLIMIT_AS` работает только на Linux. Для недоверенного кода
нужен контейнер или VM.
