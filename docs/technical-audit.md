# Технический аудит Abylkhaiyr AI Core

Исходный commit — `6acc21a`. Проверка выполнена 20 ноября 2026 года на macOS arm64, PyTorch 2.15.0, CPU и Apple MPS. До изменений Pytest дал 303 успешных проверки и 2 пропуска. Ruff прошёл, Mypy сообщил о двух ошибках для Windows API. NVIDIA RTX 4070 SUPER и CUDA на этой машине недоступны. Исторические результаты NVIDIA описаны в [документации локального обучения](local-learning.md).

| P2 | Регулярный чат и API могли учитывать разные бюджеты контекста. Top-p повторно вычислял softmax. | Подсчёт использует тот же предел, что и генерация. На CPU фильтр top-p дал идентичные выходы при четырёх порогах, медиана 3482 → 3383 мкс для 8×8192 при одном потоке, 6 чередующихся повторов. |

Ограничение checkpoint остаётся при аварии в момент **перезаписи существующего** каталога весов. Публикация нового шага использует rename, но замена существующего каталога содержит промежуток между удалением и rename. SHA-256 проверяет целостность файлов относительно метаданных. Отдельная подпись происхождения отсутствует.

## Независимый результат модели

Одинаковый полный языковой loss на pretraining test v2. Диалоговая оценка использует один набор из 53 случаев с автоматическими проверками. Ниже отдельно приведены языковые срезы. Assistant-only SFT loss вычисляется на другой выборке и здесь не сравнивается.

| Checkpoint | Test loss | Test PPL | Диалог | EN | RU | KK | Доля повторов |
|---|---:|---:|---:|---:|---:|---:|---:|
| Pretraining 6000 | 2,9787 | 19,66 | 5/53 | 12% | 5% | 12,5% | 35,5% |
| SFT-v1 1500 | 3,8405 | 46,55 | 10/53 | 28% | 15% | 0% | 16,8% |
| SFT-v3.1 40 | 3,0863 | 21,90 | 9/53 | 20% | 15% | 12,5% | 2,6% |
| SFT-v3.1 80 | 3,1004 | 22,21 | 10/53 | 28% | 5% | 25% | 7,4% |
| SFT-v3.1 120 | 3,0982 | 22,16 | 17/53 | 36% | 25% | 37,5% | 5,2% |

У всех пяти checkpoint подтверждены SHA-256, 15 735 168 параметров, словарь 8192, контекст 512 и отпечаток `c9931e24cbcc4963`. У SFT-v1 test PPL выросла в 2,37 раза. Эти результаты подтверждают ухудшение удержания базового языка. Они сами по себе не разделяют вклад LR, числа проходов и состава SFT.

В ручной проверке 14 коротких, многошаговых и длинных запросов SFT-v3.1 вернул связное приветствие на казахском и правильный alias из истории. Ошибки включали инструкцию об одном слове, перевод, арифметику, код, опечатку, длинный контекст и прямой факт. Это качественные наблюдения, без формальной метрики галлюцинаций и без заявления об отсутствии семантических пересечений.

На 94 обучающих и 19 валидационных примерах реально выполнено 2 шага SFT на MPS от SFT-v3.1 120. Обработано 1514 supervised tokens. На одинаковых 48 окнах PPL стала 22,29 → 22,27, но диалоговый результат 17/53 → 16/53, русский срез 25% → 20%. Цикл отклонил кандидат, повторный запуск вернул сохранённое решение. Указатель рабочей модели и DPO не запускались. SFT-v3.1 120 остаётся экспериментальным кандидатом.

## Производительность и интеграции

- MPS, исторический набор v3.1, одинаковый профиль, два повтора по три шага. Baseline 3163 supervised токенов/с, foreach 3269, packing 5329. Пиковая память MPS 4,16 / 4,14 / 3,08 ГиБ соответственно. Траектория loss foreach совпала с baseline на трёх шагах. Packing меняет число полезных токенов на окно, поэтому это замер throughput и памяти, а не оценка готовой модели при равном бюджете.
- В том же профилировщике baseline forward 0,155 с, backward 0,312 с, optimizer 0,008 с, загрузка 0,010 с и сохранение 0,343 с. Для packing forward 0,335 с, backward 0,742 с, optimizer 0,011 с, загрузка 0,002 с и сохранение 0,310 с. Это короткие измерения на Apple Silicon. Настройки профилей не менялись.
- Реальный inference MPS, окно 384, 32 новых токена, 3 повтора. Concat cache и preallocated дали соответственно 322 и 326 токенов/с, первый токен 9,50 и 9,43 мс. В 42 последовательных запросах RSS процесса удерживался около 571 МиБ, текущие тензоры MPS около 60 МиБ, память драйвера около 1,02 ГиБ. Такой прогон не исключает накопления памяти при большем времени и конкурентных запросах.
- На одном реальном checkpoint с одинаковыми входом и настройками ответы CLI, Inference Engine, OpenAI HTTP/SSE, Studio HTTP и WebSocket совпали. Успешны ping/pong и восстановление сохранённого текста по request ID после переподключения. Неизвестный маршрут вернул JSON/404, пользователь без сессии получил 401. Проверка выполнена с изолированным ASGI-приложением и отдельной SQLite. Существующие Studio и обучение не перезапускались.
- Developer Agent в реальном Docker с этим checkpoint выполнил 0 из 4 задач: сумма, сортировка, исправление Python и SQL. Команды и входы были изолированы, критерии приёмки фиксированы. Текущий агент ориентирован на один файл Python с ограниченными retry. Java/REST, автономная работа над проектом, сборка и тесты многофайловых приложений этой реализацией не покрываются.

## Воспроизведение

Сырые локальные результаты, включая ответ модели, сохранены в игнорируемой папке `experiments/audit_current`. Для Docker требуется уже имеющийся локальный образ с Python и его полный SHA-256 ID.

```bash
.venv/bin/ruff check .
.venv/bin/black --check -q src tests scripts
.venv/bin/mypy src
ABYLKHAIYR_TEST_IMAGE="$LOCAL_PYTHON_IMAGE" .venv/bin/pytest -o addopts='' -q -rs
.venv/bin/python scripts/evaluate_sft.py --split test --retention-only \
  --output experiments/audit_current/quality.json \
  base=checkpoints/tiny_v2/tiny_best legacy=checkpoints/tiny_v2_sft/tiny_sft_best \
  v31_40=checkpoints/tiny_v31_sft_stage11/step-00000040 \
  v31_80=checkpoints/tiny_v31_sft_stage11/step-00000080 \
  v31_120=checkpoints/tiny_v31_sft_stage11/step-00000120
.venv/bin/python scripts/inference_benchmark.py checkpoints/tiny_v31_sft_stage11/step-00000120 \
  --prompt-tokens 32 128 384 --new-tokens 32 --repeats 3 \
  --output experiments/audit_current/inference.json
.venv/bin/python scripts/profile_training.py --config configs/tiny_v31_sft.yaml --device mps \
  --variants baseline foreach packed --steps 3 --repeats 2 --phases --stability-steps 3 \
  --output experiments/audit_current/training_profile.json
.venv/bin/python scripts/evaluate_developer_agent.py \
  --checkpoint checkpoints/tiny_v31_sft_stage11/step-00000120 --image "$LOCAL_PYTHON_IMAGE" \
  --output experiments/audit_current/developer
.venv/bin/python scripts/continuous_learning.py --device mps \
  --reference checkpoints/tiny_v31_sft_stage11/step-00000120 --evaluation-data data/v2 \
  --inbox experiments/audit_current/learning-inbox --work experiments/audit_current/learning \
  --seed-math --steps 2
.venv/bin/python scripts/build_instruction_corpus.py --source-dir data/v2 \
  --output-dir experiments/audit_current/clean_sft
```
